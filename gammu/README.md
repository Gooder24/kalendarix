# Kalendarix → phone via Gammu

These scripts upload a calendar exported from Kalendarix (a `.vcs` file)
straight into an old phone using the **Gammu** tool.

Every script comes in two versions: `*.bat` for **Windows** and `*.sh`
for **macOS / Linux** (same behaviour).

| Script (Windows / macOS·Linux) | Phones | Format |
|--------|----------|--------|
| `nokia-s40.bat` / `nokia-s40.sh` | Nokia Series 40 (3310, 6300, C2-01, 6700, Asha) | vCalendar 1.0 |
| `nokia-s60.bat` / `nokia-s60.sh` | Nokia S60 / Symbian (N95, E71, 6600, N70) | iCalendar 2.0 |
| `sonyericsson.bat` / `sonyericsson.sh` | Sony Ericsson (W800, K750, W810, K800) | vCalendar 1.0 |
| `generic.bat` / `generic.sh` | Motorola, Samsung, Siemens/BenQ and others | vCalendar 1.0 |

---

## 1. Installing Gammu (once)

### Windows

1. Download Gammu for Windows: <https://wammu.eu/gammu/> (the *Download* section).
2. Install it to `C:\Program Files\Gammu` (the scripts expect
   `C:\Program Files\Gammu\bin\gammu.exe`). If it is somewhere else, edit the line
   `set GAMMU=...` in the relevant `.bat`.
3. Check the installation:
   ```
   "C:\Program Files\Gammu\bin\gammu.exe" --version
   ```

### macOS

```
brew install gammu
gammu --version
```

### Linux

```
sudo apt install gammu       # Debian / Ubuntu / Mint
sudo dnf install gammu       # Fedora / RHEL
sudo pacman -S gammu         # Arch / Manjaro
sudo zypper install gammu    # openSUSE
gammu --version
```

The `.sh` scripts look for `gammu` in `PATH`. If you have it elsewhere, run the script with
a variable: `GAMMU=/path/to/gammu ./nokia-s40.sh`.

> **Linux — access to the USB port.** For Gammu to see the phone without `sudo`, add
> yourself to the `dialout` group (Debian/Ubuntu/Arch) or `uucp` (Fedora):
> `sudo usermod -aG dialout $USER`, then log out and back in.

## 2. Connecting the phone (USB mode)

The most common cause of “phone not found” is the wrong USB mode. After you plug in
the cable, the phone usually offers a menu — choose **data / phone mode**, NOT
“mass storage / File transfer / MSC”.

| Brand | Correct USB mode |
|--------|-------------------|
| Nokia S40/S60 | **PC Suite** (not “Mass storage” / “Media transfer”) |
| Sony Ericsson | **Phone mode** (not “File transfer”) |
| Motorola | **Motorola Phone Tools / Modem** (not “USB Mass Storage”) |
| Samsung | **Samsung PC Studio / Modem** |
| Siemens / BenQ | data cable + **Modem** profile |

> Tip: if the phone has no USB but does have Bluetooth, Gammu can use BT too — see
> the *gammurc* section below.

## 3. Setting up Gammu (gammurc)

Gammu needs to know which port the phone listens on. The simplest way:

```
gammu-detect
```

Output (example):

```
; Configuration file generated by gammu-detect.
[gammu]
device = com7:
name = Phone on COM port 7
connection = at
```

Copy the `[gammu]` block into a file named `gammurc`:

- save it either to `%USERPROFILE%\gammurc` or next to `gammu.exe`,
- common `connection` values:
  - `at` — most Nokia S40, Sony Ericsson, Samsung, Siemens (AT over a modem),
  - `at115200` — if `at` is slow/unstable,
  - `symbian` or `blueobex`/`irdaobex` — some S60 over OBEX.

Check the connection:

```
"C:\Program Files\Gammu\bin\gammu.exe" identify
```

Example of a successful output:

```
Device               : com7:
Manufacturer         : Nokia
Model                : 6300 (RM-217)
Firmware             : 07.20
IMEI                 : 35XXXXXXXXXXXXX
```

If you see `Manufacturer`/`Model`, the connection works and you can run the `.bat`.

## 4. Export and run

1. In Kalendarix open **Settings → Export to a phone** (*Nastavenia → Export do
   telefónu* in the Slovak interface), choose the model, export.
   Save the file to the **Desktop** as `kalendarix-export.vcs`
   (the scripts look for exactly `%USERPROFILE%\Desktop\kalendarix-export.vcs`).
2. Run the script for your brand:
   - **Windows:** double-click the `.bat`.
   - **macOS / Linux:** in a terminal in this folder:
     ```
     chmod +x nokia-s40.sh   # once, makes it executable
     ./nokia-s40.sh
     ```
3. The script runs `gammu identify` (connection check) and then
   `gammu restore "<.vcs>"`, which uploads the events into the phone's calendar.

> A different file name/location? Edit `set VCS=...` in the `.bat`, or run the
> `.sh` with a variable: `VCS=/path/to/export.vcs ./nokia-s40.sh`.

## 5. Known quirks by brand

**Nokia Series 40**
- Maximum length of an event title ~40 characters (Kalendarix truncates automatically).
- Diacritics go through QUOTED-PRINTABLE/UTF-8 — works on most models.
- Alarm = `AALARM` (absolute time), only simple recurrences (D/W/MD/YM).

**Nokia S60 (Symbian)**
- Full iCalendar 2.0: `VEVENT` + `VALARM` + `VTIMEZONE` + `UID`, categories.
- Times are tied to the `Europe/Bratislava` zone (CET/CEST).
- If `restore` reports a format error, try `gammu addnew "<.vcs>"`.

**Sony Ericsson**
- USB must be in “Phone mode”. In “File transfer” Gammu does not see the phone.
- Event title max ~35 characters.
- Some models need `connection = at19200` in `gammurc`.

**Motorola RAZR / ROKR** (`generic.bat`)
- Only **ISO-8859-1** (Latin-1) — Slovak diacritics such as č/š/ž are
  transliterated to c/s/z. This is intentional, the phone cannot display them.
- No location field (LOCATION), title max ~32 characters.
- USB mode “Modem”, not “Mass Storage”.

**Samsung (feature)** (`generic.bat`)
- vCalendar 1.0, UTF-8. USB via “PC Studio / Modem”.

**Siemens / BenQ-Siemens** (`generic.bat`)
- The strictest: **no recurrences**, no location, title max ~30 characters, Latin-1.

## 6. Troubleshooting

| Symptom | Solution |
|---------|----------|
| `Telefon nenajdeny` (“phone not found”) | Check the USB mode (section 2), run `gammu-detect`, check `gammurc`. |
| `Error opening device` / port busy | Close PC Suite/PC Studio/Wammu — another program is holding the port. |
| `No response in specified timeout` | Try a different `connection` (`at`, `at115200`, `at19200`) or another USB port/cable. |
| Diacritics come out garbled | For Motorola/Siemens this is expected (Latin-1). For the others, check that the export used the right profile. |
| `restore` fails on S60 | Try `gammu addnew "<.vcs>"` (adds events instead of overwriting). |
| Events uploaded, but at the wrong time | Check the time/zone in the phone; S60 uses `Europe/Bratislava`. |

Manually (without a script):

```
# Windows
"C:\Program Files\Gammu\bin\gammu.exe" identify
"C:\Program Files\Gammu\bin\gammu.exe" restore "%USERPROFILE%\Desktop\kalendarix-export.vcs"

# macOS / Linux
gammu identify
gammu restore "$HOME/Desktop/kalendarix-export.vcs"
```

> Note: `restore` may overwrite existing calendar entries. If you only want to
> add, use `addnew`.
